# 1. 当前页面存在的问题与改版结论

## 1.1 当前截图中可以看到的问题

当前页面已经有较完整的功能，但视觉信息顺序不符合医生的阅读需求：

- 顶部五个概览卡片横向压缩，文字换行严重，显得拥挤。
- “证据联查”模块高度较大、位置较重，压过了真正应该最突出显示的患者病程时间线。
- 当前时间轴把**原始材料缩略图放在最上层**，医生第一眼看到的是一排单据，而不是“什么时候发生了什么”。
- 时间轴卡片中的事件说明区域偏小，且证据、标签、材料入口之间层级不明确。
- 右侧详情区仍是多个平级区块堆叠，没有形成“先读事件，再看证据，再核验材料”的阅读顺序。
- 已有蓝色高亮、红框等视觉信号较多，但没有统一表达“事件 / 证据 / 既往记录 / 原始材料”的语义层级。

## 1.2 本轮改版的最终决策

本次必须进行真正的 **content-first timeline redesign**：

```text
医生阅读优先级：
时间与事件说明
    ↓
支撑该事件的证据链
    ↓
既往医生记录 / 既往诊断原文（仅在材料明确存在时）
    ↓
对应原始病历材料入口
```

### 最关键的结构改变

当前设计：

```text
原始病历图片缩略图（视觉最强）
↓
时间轴圆点和日期
↓
简短节点卡片
```

改为：

```text
时间轴日期和节点状态
↓
事件说明卡片（视觉最强）
↓
证据链摘要
↓
既往医生记录 / 既往诊断原文
↓
原始材料附件链接（视觉最轻，点击查看图片）
```

**原始单据缩略图不再作为每个时间节点最上方的大面积视觉内容。**  
原图仍然重要，但应作为“证据核验入口”，出现在节点卡片底部附件行、右侧详情面板或点击后的高亮证据弹窗中。

# 4. 各区域具体设计说明

## 4.1 A 区：顶部品牌导航栏

### 目标
只承担品牌识别、数据边界提示和少量一级操作，不承担病历详情展示。

### 目标结构

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ 转诊迹                                                                       │
│ 转院病历证据时间轴          合成演示材料｜不构成诊断或治疗建议   [采集材料] [摘要] │
└──────────────────────────────────────────────────────────────────────────────┘
```

### UI 规格建议

| 元素 | 建议 |
| --- | --- |
| 高度 | 68–76px |
| 产品名 | 20–22px，semibold，深色 |
| 副标题 | 13–14px，灰色 |
| 安全提示 | 小型浅灰/浅蓝 badge，不能过红抢眼 |
| 主按钮 | `采集材料` 为主按钮；`摘要` 为次按钮 |
| 背景 | 白色或极浅灰，不使用大渐变 |

### 必须避免

- 不要把患者、节点数、材料覆盖全部塞到导航栏；
- 不要在导航栏出现大面积卡片；
- 不要让按钮数量超过 2–3 个。

## 4.2 B 区：轻量患者概览栏

### 目标
解决当前左上方五张卡片拥挤、换行混乱的问题。概览只提供阅读上下文，不应成为页面视觉焦点。

### 推荐布局

采用一个整体 panel，内部使用“主信息 + 状态信息”的两列结构：

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ 演示患者 A01  女，62岁       青禾县中心医院 → 澄明医学中心      目标科室：心内科 │
│ 材料覆盖：2024-03-12 至 2025-01-16  ·  6 个节点  ·  待核验字段 4 项  · 新增 0 份 │
└──────────────────────────────────────────────────────────────────────────────┘
```

或在超宽屏上拆为：

```text
┌──────────────────────────┬───────────────────────────────────────────────────┐
│ 演示患者 A01              │ 青禾县中心医院 → 澄明医学中心     心内科           │
│ 女，62岁                  │ 2024-03-12 至 2025-01-16 · 6 节点 · 待核验 4 项  │
└──────────────────────────┴───────────────────────────────────────────────────┘
```

### UI 规格建议

| 元素 | 建议 |
| --- | --- |
| 区域高度 | 82–106px |
| panel 背景 | `#FFFFFF` / `#F8FAFC` |
| 边框 | 极浅 1px |
| 间距 | 外边距 20–24px，内部 16–20px |
| 信息标签 | 12px，灰色 |
| 主值 | 14–16px，medium/semibold |
| 状态项目 | 使用点分隔或小型轻 badge，不做五个厚重卡片 |

## 4.3 C 区：证据联查与筛选工具栏

### 目标
保留功能，但把它降级为辅助工具，不再占据一大块首屏空间。

### 默认未搜索状态线框

```text
┌────────────────────────────────────────────────────────────────────────────────┐
│ 证据联查  [ 输入问题，在现有材料中定位相关原文证据……                    ] [查找] │
│           仅归纳已上传材料原文，不生成诊断或治疗建议。 · 本地检索模式          │
│                                                                                │
│ 筛选： [全部节点] [只看异常] [与转院原因相关] [材料类型 ▾]        [重置]      │
└────────────────────────────────────────────────────────────────────────────────┘
```

### 规则

- 整体比当前模块更紧凑；
- 证据联查标题使用 13–14px，不使用大标题；
- 搜索框高度约 40px；
- “检索词”说明可在搜索后展开，而非默认占多行；
- 搜索结果不要默认把时间轴向下挤出首屏：可放在时间轴下部折叠区域，或在右侧切换为“联查结果”阅读状态。

### 搜索有结果后的两种推荐形式

优先采用形式 A：**主时间轴仍在视野内，结果在时间轴下方折叠展开**。

```text
时间轴卡片区域
────────────────────────────────────────
关联结果（2）  [收起]
2025-01-09｜门诊病历｜直接提及
“患者近一周食欲欠佳，进食量较前减少。” [查看证据]
2025-01-12｜入院记录｜同义表述
“食欲不振，否认明显呕吐。”               [查看证据]
```

不要把证据联查结果变成大面积首屏主内容，除非用户主动进入专门的检索结果视图。

| L5 | 既往医生记录/既往诊断原文 | 有原文时显示 | 暖灰/紫/琥珀浅底；明确不是系统判断 |
| L6 | 原始材料入口 | 是 | 灰色轻量附件行，点击查看 |

### 文案边界

“既往医生记录 / 既往诊断原文”必须满足：

- 只有材料中实际存在相关表述时才展示；
- 系统不得把 OCR 片段自行升级为“医生判断”；
- 如果原材料只写了检查值，就只放在证据链，不展示为既往医生判断；
- 推荐标签：
  - `既往医生记录`
  - `既往诊断原文`
  - `材料原文记载`
- 避免标签：
  - `AI 判断`
  - `诊断结论`
  - `建议处理`
