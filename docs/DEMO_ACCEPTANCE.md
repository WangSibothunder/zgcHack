# Demo 验收清单

完成后由 Codex 将本文件复制为可勾选报告，或在 `DEMO_COMPLETION_REPORT.md` 逐项记录命令、截图路径或手工验证结果。

## A. 产品闭环

- [ ] 打开页面可看见“合成演示数据/不构成诊断或治疗建议”提示。
- [ ] 可选择或默认进入至少 3 个合成转院病例之一。
- [ ] 心内科病例显示 6 个按日期升序排列的节点。
- [ ] 每个节点上方有合成材料缩略图，下方有结构化概要。
- [ ] 点击节点后详情区更新：字段、OCR、证据、置信度、材料预览。
- [ ] 点击证据可打开原始合成材料并定位对应字段。
- [ ] 可显示材料缺失提醒，且文案不是医学判断。

## B. 交互闭环

- [ ] 时间轴可以横向滚动并在窄屏可用。
- [ ] “只看异常”筛选有效。
- [ ] “材料类型”筛选有效。
- [ ] “与转院原因相关”筛选有效。
- [ ] 加载、空结果、错误重试、低置信度状态有界面反馈。
- [ ] 模拟上传后显示处理完成并进入对应生成病例。

## C. 技术闭环

- [ ] 前端与后端为可独立启动的工程。
- [ ] 前端实际通过 HTTP 请求加载病例和节点数据。
- [ ] 后端提供健康检查、病例、时间轴、材料、上传任务接口。
- [ ] JSON fixture 校验通过：synthetic 标识、节点排序、引用完整。
- [ ] 后端测试通过；前端构建/测试通过。
- [ ] README 从干净环境可按步骤启动演示。
- [ ] 没有真实病例、个人信息、密钥或 `.env` 被提交。

## D. 发布闭环

- [ ] 形成 `docs/DEMO_COMPLETION_REPORT.md`，记录验收证据。
- [ ] Git 提交历史清晰。
- [ ] 已在通过全部验收后创建私有 GitHub 仓库 `zgcHack` 并推送。
