# 合成病历数据与演示安全约束

## 当前阶段

当前阶段仅用于黑客松 Demo。`demo-data/` 中的患者、医院、时间线、OCR 文本、检查字段和原始材料 SVG 均为虚构生成，并用来证明页面交互与证据追溯流程可工作。

## 禁止写入仓库的内容

- 真实患者的姓名、证件号、联系方式、住址、条码/二维码。
- 真实病例图片、真实电子病历截图、真实医院导出的报告。
- 医院内部账号、密钥、访问 token、环境文件。
- 带有可识别个人隐私的录屏或截图。

## UI 文案规则

推荐：
- “合成演示数据”
- “异常字段待核验”
- “OCR 提取内容，请结合原始材料核验”
- “材料完整性提示”
- “不构成诊断或治疗建议”

禁止：
- “系统诊断为……”
- “应立即接受……治疗”
- “AI 已确认病情……”
- “根据本系统可替代医生判断”

## 进入真实病例阶段前的门槛

后续如需使用真实材料，必须先独立设计并评审：授权与知情同意、脱敏、访问控制、存储加密、日志审计、数据删除/保留政策、错误纠正流程和部署合规要求。在完成这些工作前，保持 synthetic-only 模式。
