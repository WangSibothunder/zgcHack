病历时间轴重建系统设计文档
1.1 项目概述
本项目面向患者转院场景，构建一个病历快速重建与证据追溯系统。
在患者从原医院转入新医院时，由于不同医院电子病历系统通常无法直接互通，患者往往需要携带大量纸质病历、检查报告、出院小结、影像报告和化验单。新医院医生需要在较短接诊时间内快速理解患者既往诊疗过程，但现有纸质材料常存在顺序混乱、格式不统一、信息量大、关键内容难以定位等问题。
系统的核心目标是：
在转院患者候诊或入院前，将其携带的纸质病历快速转化为一条可滑动、可核验、可追溯的病情时间轴，帮助接诊医生快速建立患者既往诊疗上下文。
系统采用“一个时间点一个节点”的横向时间轴设计。每个时间节点上方展示该时间对应的原始病历图片，下方展示系统生成的结构化概要。用户可以左右滑动浏览不同时间点的病历记录，也可以点击节点查看原图、OCR 文本、关键指标、诊疗摘要和证据来源。
会议纪要中已经明确提到，当前医院间病历系统互通存在困难，转入新医院时往往需要将纸质病历快速转为电子材料，而快速重建完整病历对医生有实际价值。

---
1.2 产品定位
2.1 一句话定位
面向转院患者，把其携带的杂乱纸质病历快速重建成医生可阅读、可追溯的病情时间轴。
2.2 核心场景
本产品的核心场景不是普通健康档案管理，也不是慢病日常记录，而是：
患者从 A 医院转入 B 医院，新医院无法直接读取原医院电子病历，患者只能携带纸质材料或截图。系统在患者候诊、入院登记或医生接诊前，完成病历数字化、时间排序、概要生成和证据绑定。
2.3 产品边界
系统不替代医生诊断，不给最终治疗建议。
系统只做四件事：
1. 将纸质病历转为电子材料；
2. 按时间重建患者既往诊疗过程；
3. 提取每个时间点的关键信息；
4. 让医生能从概要回到原始证据。
产品价值应表达为：
缩短转院患者病历接收和理解时间，降低医生从杂乱材料中重建病情上下文的成本。

---
1.3 应用场景
3.1 场景背景
患者因病情加重、治疗效果不佳、原医院诊疗能力有限或希望获得更高层级医院诊疗，选择从原医院转入新医院。
在转院过程中，患者通常会携带：
1. 原医院门诊病历；
2. 入院记录；
3. 出院小结；
4. 检查报告；
5. 化验单；
6. 影像报告；
7. 手术记录；
8. 用药记录；
9. 医生手写记录；
10. 既往诊断证明。
这些材料可能来自多个时间点、多个科室、多个医院，格式不统一，顺序混乱，甚至存在拍照模糊、材料缺页、日期不清等问题。
新医院医生接诊时，需要先回答几个问题：
1. 患者为什么转院？
2. 原医院做过哪些检查？
3. 原医院给出的诊断是什么？
4. 治疗过程如何？
5. 哪些指标异常？
6. 病情是好转、恶化还是反复？
7. 是否存在关键遗漏材料？
8. 哪些信息和本次接诊最相关？
系统要解决的就是这个“转院病历上下文重建”问题。

3.2 典型业务流程
阶段一：患者到达新医院
患者到达新医院后，在候诊区、导诊台、入院登记处或转诊接待窗口提交既往病历材料。
材料形式包括：
1. 纸质病历；
2. 手机拍照；
3. PDF；
4. 微信聊天中保存的报告截图；
5. 医院公众号下载的检查单；
6. 原医院打印出的出院记录。
阶段二：导诊人员或患者上传材料
如果患者操作能力较强，可以自行上传。
如果患者年龄较大或材料较多，由导诊人员、护士或陪诊人员协助上传。
上传方式包括：
1. 批量拍照；
2. 扫描仪扫描；
3. 相册导入；
4. PDF 上传；
5. 多张病历平铺拍摄后自动切割。
阶段三：系统自动处理
系统自动完成：
1. 图片质量检测；
2. 图像切割和矫正；
3. OCR 识别；
4. 日期识别；
5. 医院和科室识别；
6. 材料类型分类；
7. 诊断、检查、指标、用药、治疗信息抽取；
8. 同一天材料聚合；
9. 生成横向时间轴；
10. 为每条概要绑定原始证据位置。
阶段四：医生查看时间轴
医生打开患者病历时间轴后，先看到按时间排列的病历节点。
每个节点代表一个具体时间点：
2024-03-12    2024-05-08    2024-09-21    2025-01-15
每个节点上方展示原始图片缩略图，下方展示该时间点概要。
医生可以：
1. 左右滑动浏览患者既往诊疗过程；
2. 点击某个时间节点查看详情；
3. 点击原始图片放大核验；
4. 点击指标查看历史趋势；
5. 点击摘要字段追溯原始证据；
6. 筛选与本次转院原因相关的病历。
阶段五：医生形成接诊上下文
医生通过时间轴快速了解：
1. 原医院诊疗过程；
2. 病情变化趋势；
3. 已完成检查；
4. 已尝试治疗；
5. 当前转院原因；
6. 下一步需要补充的信息。
系统完成的是“接诊前病历整理”，不是“诊断替代”。

4. 用户故事
4.1 转院患者：提交既往病历
作为一名从外院转入新医院的患者，我希望能在候诊或入院登记时一次性上传既往病历材料，让新医院医生快速看到我之前的检查、诊断和治疗过程，而不用我反复口头解释病情。
验收标准
1. 患者可以批量上传纸质病历图片或 PDF；
2. 系统能提示上传进度和处理状态；
3. 上传后生成可查看的病历时间轴；
4. 患者可以选择是否分享给医生；
5. 患者可以删除或隐藏不想展示的材料。

---
4.2 导诊人员：协助患者录入转院材料
作为一名新医院导诊人员，我希望能帮助转院患者快速扫描或拍摄原医院病历，让系统自动整理成时间轴，避免患者因为不会操作手机或材料太多而无法完成上传。
验收标准
1. 支持批量拍照或扫描；
2. 支持多张材料连续上传；
3. 系统自动检测模糊、反光、缺角图片；
4. 对无法识别日期的材料标记为“待确认”；
5. 处理完成后生成医生可查看的整理页。

---
4.3 接诊医生：快速理解患者为什么转院
作为一名接收转院患者的医生，我希望打开系统后能立刻看到患者既往诊疗的时间线，快速判断患者为什么转院、之前做过哪些检查、原医院给出过什么诊断，以及病情是否发生变化。
验收标准
1. 时间轴按日期从早到晚排列；
2. 一个时间点对应一个节点；
3. 节点下方显示简明概要；
4. 概要包括医院、科室、材料类型、诊断、关键指标和处理措施；
5. 医生可以左右滑动浏览完整病史。

---
4.4 接诊医生：核验原始材料
作为一名医生，我希望系统生成的每条概要都能回到原始病历图片，这样我可以判断 AI 提取内容是否可靠，而不是只能看到无法验证的总结。
验收标准
1. 点击概要中的诊断、指标或治疗信息后，可以定位到原始图片；
2. 原始图片支持放大、缩小和切换；
3. OCR 文本与原始图片位置对应；
4. 低置信度内容有明显提示；
5. 医生可以查看同一时间点下的全部原始材料。

---
4.5 接诊医生：筛选与本次转院原因相关的病历
作为一名医生，我希望能根据本次转院原因筛选病历，例如只看肿瘤相关、心血管相关、内分泌相关或术后并发症相关的材料，从而减少无关病历干扰。
验收标准
1. 支持按病种筛选；
2. 支持按科室筛选；
3. 支持按材料类型筛选；
4. 支持按异常指标筛选；
5. 筛选后时间轴仍保持时间顺序；
6. 被隐藏节点可以随时恢复查看。

---
4.6 转院患者家属：补充病历材料
作为一名患者家属，我希望能在医生查看前继续补充遗漏的病历图片，例如某次检查报告或出院记录，让医生看到更完整的转院背景。
验收标准
1. 家属可以追加上传材料；
2. 新材料处理后自动插入对应时间节点；
3. 如果日期无法识别，系统提示用户手动确认；
4. 新增材料会标记为“新上传”；
5. 医生端时间轴同步更新。

---
4.7 医生：发现关键材料缺失
作为一名接诊医生，我希望系统能提示某些关键时间段或关键材料可能缺失，例如只有出院小结但没有检查报告，只有化验单但没有诊断记录，从而帮助我判断是否需要患者补充材料。
验收标准
1. 系统能识别材料类型分布；
2. 对明显缺失的关键材料给出提示；
3. 缺失提示不应伪装成医学判断；
4. 医生可以一键生成“需补充材料清单”；
5. 患者或家属可以根据清单继续上传。

5. 核心交互流程
5.1 转院材料上传流程
患者到达新医院
  ↓
患者或导诊人员上传原医院病历
  ↓
系统检测图片质量
  ↓
OCR 和结构化抽取
  ↓
按日期聚合为时间节点
  ↓
生成横向病历时间轴
  ↓
患者确认分享给医生
  ↓
医生查看并核验原始证据

---
5.2 医生查看流程
医生打开患者转院病历页
  ↓
查看顶部转院摘要
  ↓
横向滑动时间轴
  ↓
点击关键时间节点
  ↓
查看概要、原图、OCR、指标
  ↓
筛选与本次转院原因相关材料
  ↓
确认既往诊疗过程和缺失信息

6. 时间轴页面设计
6.1 页面结构
┌────────────────────────────────────────────┐
│ 患者信息｜转院原因｜原医院｜目标科室｜筛选入口 │
├────────────────────────────────────────────┤
│ 原始图片缩略图   原始图片缩略图   原始图片缩略图 │
│      │               │               │        │
│ ──── ● ───────────── ● ───────────── ● ───→   │
│      │               │               │        │
│  时间概要卡片     时间概要卡片     时间概要卡片  │
├────────────────────────────────────────────┤
│ 当前节点详情：原图 / OCR / 摘要 / 指标 / 证据 │
└────────────────────────────────────────────┘
6.2 顶部信息区
顶部不再泛泛显示“患者病历”，而是突出转院信息：
1. 患者基本信息；
2. 原医院；
3. 转入医院；
4. 转入科室；
5. 转院原因；
6. 病历覆盖时间；
7. 已识别材料数量；
8. 关键异常指标数量；
9. 缺失材料提示。
示例：
患者：张某，男，62 岁
转院：XX 县医院 → XX 三甲医院心内科
转院原因：胸痛反复发作，原医院建议进一步检查
病历范围：2024-03-12 至 2025-01-15
已识别：42 张材料，生成 11 个时间节点

---
6.3 时间节点设计
每个节点对应一个时间点。
节点上方：
原始病历图片缩略图
节点中间：
时间轴圆点 + 日期
节点下方：
结构化概要卡片
概要卡片格式：
2025-01-15
XX 县医院｜心内科
胸痛复诊，心电图异常
肌钙蛋白升高，建议转上级医院
同一天多份材料时：
2025-01-15
XX 县医院｜心内科
材料：门诊病历 + 化验单 + 心电图报告
异常：肌钙蛋白升高

7. MVP 范围修订
7.1 MVP 必做
MVP 只服务转院场景。
必须实现：
1. 转院患者病历上传；
2. 批量图片或 PDF 录入；
3. OCR；
4. 日期识别；
5. 同一天材料聚合；
6. 一个时间一个节点；
7. 横向滑动时间轴；
8. 节点上方原始图片；
9. 节点下方结构化概要；
10. 点击节点查看详情；
11. 点击原图放大核验；
12. 简单筛选；
13. 生成医生查看页。
7.2 MVP 暂不做
1. 慢病长期管理；
2. 普通健康档案；
3. AI 诊断建议；
4. 治疗方案推荐；
5. 医院 HIS/EMR 深度集成；
6. 院间数据自动互通；
7. 多年级别复杂病历管理；
8. 自动医学推理结论。
7.3 MVP 验证问题
第一版只验证：
1. 转院病历能否被快速上传；
2. 时间轴是否比图片列表更易读；
3. 医生是否能更快理解患者既往诊疗过程；
4. 医生是否信任“概要 + 原图追溯”的形式；
5. 候诊或入院登记阶段是否能完成材料处理；
6. 系统是否能帮助医生发现缺失材料。

8. 对外表达版本
8.1 路演版
我们聚焦转院场景。患者从原医院转入新医院时，由于医院间电子病历通常无法互通，医生需要在短时间内阅读大量纸质病历和检查报告。我们的系统通过 OCR、结构化抽取和时间排序，把这些杂乱材料重建成一条横向病历时间轴。一个时间点一个节点，节点上方保留原始图片，下方展示 AI 提炼概要，医生可以快速浏览病情发展，也可以点击回到原始证据核验。
8.2 更短版本
我们为转院患者做病历快速重建，把原医院带来的纸质病历整理成医生可滑动查看的时间轴。每个时间点上方是原始图片，下方是结构化概要，解决新医院医生快速理解既往诊疗过程的问题。

---
9. 设计结论
修改后，整个产品应围绕一个明确问题展开：
转院患者进入新医院时，如何让医生快速获得原医院诊疗过程的可信上下文。
所以文档中所有内容都应围绕转院，不再并列写慢病、疑难病、复诊等泛化场景。
最终主线应固定为：
1. 患者转院；
2. 原医院病历无法直接互通；
3. 患者携带纸质材料；
4. 新医院医生需要快速理解既往诊疗过程；
5. 系统上传并识别材料；
6. 按时间生成节点；
7. 节点上方原图、下方概要；
8. 医生滑动浏览；
9. 点击节点核验证据；
10. 辅助医生建立转院接诊上下文。
